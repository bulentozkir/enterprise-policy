ALZ POLICY DEFINITIONS - TERRAFORM

Provide the target explicitly with -TenantId, -SubscriptionId and
-ManagementGroupName. For a tenant root deployment, the management-group name is
the tenant ID. -ExpectedUserPrincipalName must match the existing Azure CLI user.
The subscription is used only for authentication, not as the deployment scope.

Creates custom policy definitions and exactly three initiatives: Global, Hub,
LandingZone. It creates NO policy assignments, role assignments, managed identities,
remediation jobs, or workload resources. Definitions alone do not enforce policy.

Use the existing Azure CLI authentication for the requested tenant. An Edge portal
session alone is not Terraform authentication. The account needs Resource Policy
Contributor or equivalent permissions on the target management group. Reader and
Entra directory administrator roles alone do not grant Azure Policy write access.
The script does not change sign-in, permissions, or roles. It restores any
temporary provider-subscription selection when the run finishes.

Plan only:
  .\deploy.ps1 -TenantId <TENANT_ID> -SubscriptionId <SUBSCRIPTION_ID> -ManagementGroupName <MANAGEMENT_GROUP_NAME> -ExpectedUserPrincipalName <USER_UPN> -AcknowledgeCoverageGaps
Plan, inspect for unexpected resource types/deletions, then apply:
  Use the same target arguments and add -Apply.

The supplied source catalog must be complete before plan/apply. Missing definitions
are hard failures; empty initiatives and partial deployments are not substituted.
The catalog records the Key Vault certificate-expiry and Service Health billing
limitations, the requested removals (R18/R20/R21/R23/R24/R25/R31/R32/R34/R35/R36, H11/H20 and L49), and the
H17/L10/L11 address/path/range omissions. After reviewing all gaps, accept them with:
  -AcknowledgeCoverageGaps
This switch NEVER bypasses the missing-source guard.

Do not run apply until catalog.json reports no missing rows and policy/initiative
sources have been reviewed. Built-in/custom source validation is separate from
Terraform syntax validation; an Azure API import may report additional alias/rule
constraints. Existing Azure definitions must be imported into Terraform state before
management, not overwritten blindly. prevent_destroy rejects deletion/replacement.

There are 75 definitions (Global 23, Hub 12, LandingZone 40) and three initiatives.
Policy defaults remain Audit/AuditIfNotExists. Prefer Portal pickers, fixed-choice
dropdowns; no Boolean text boxes, free-form objects or scalar text. All true/false
inputs are String dropdowns with choices "true"/"false" and default "true".
Rules convert them with bool(), including Kubernetes Boolean values. Editable arrays have
three replaceable defaults: R04/R05/R06 mandatoryTags start with owner, costcenter,
environment and are not restricted to these names or to three entries.
Conditional enabled switches default to "true"; "true" evaluates all matching
resources within the assignment scope and "false" skips. Global r26_enabled controls
both Windows VM/VMSS Hybrid Benefit checks without selecting VMs. Confirm licensing
eligibility before assigning and select "false" for ineligible scopes. R26/R27 require
separate eligible scopes; disable the inapplicable check. Use assignment exclusions
or exemptions for exceptions. All other true/false inputs also default to "true",
including L13 allowHostNetwork; host ports remain disallowed.
Target-resource and exception selection inputs are removed; resource pickers remain
only for necessary destinations and peer networks. H07 checks each
Public IP's DDoS protectionMode: Enabled passes without requiring a plan. Inherited
or unspecified protection is reported for separate verification.
Terraform definition creation needs no future assignment values, but assignments
still require the destination pickers and dropdowns listed in required-inputs.json.

The current 75-definition revision (Global 23, Hub 12, LandingZone 40) and its three
initiatives were deployed and verified at the requested tenant root management
group on 2026-11-04: plan 79 to add / 0 change / 0 destroy (75 definitions,
3 initiatives, 1 tracking resource), zero live content differences and no Terraform
drift. The previous 84-definition deployment of this package was unassigned and,
at the owner's request, was deleted first (3 initiatives, then 84 definitions);
182 unrelated custom definitions and 12 other initiatives were not touched. The
old Terraform state was kept in a state-backup folder beside the new state.
The source removes R24, all four R25 variants, R34, H11/H20 and L49, corrects and
renames H07/L14, and uses default-true dropdowns. L49's remote-gateway and
hub-selection inputs are removed entirely. L14 now checks that AKS local
accounts are disabled, not only that Microsoft Entra integration is present;
L15 remains unchanged and overlaps this check. No assignments, exemptions or role
assignments were created.
Removing/renaming Azure Policy parameters or changing their types is not supported
in place. Assignment values for dropdowns must be quoted strings, not Booleans.
For other deployments that hold an earlier revision with assignments, use a fresh
target or a separately reviewed migration to versioned policy/initiative
definitions; do not apply directly over an existing 84- or 97-definition package.
Deleting deployed definitions requires migration review. prevent_destroy and the
deployment script's deletion guard are intentionally retained.

State and provider files used by deploy.ps1 are stored under LOCALAPPDATA, not in
the source folder. The runtime key includes both tenant and management-group name,
so changing management groups cannot accidentally reuse another target's state.
The provider lock file stays with source.
Policy definitions and initiatives use Terraform AzAPI with stable ARM API
2026-07-01; AzureRM is used only for the authentication-identity precondition.
The AzureRM policy client calls a retired preview API and is not used for writes.
imports.tf can adopt already-existing package definitions into state through the
existing_policy_imports variable (empty by default).

AUTHENTICATION
deploy.ps1 verifies the requested user, tenant, enabled subscription, management
group, effective write permissions and token principal. Permission checks use
authenticated az rest calls without manually constructing authorization headers.
The script temporarily selects the provider
subscription for tenant-token acquisition. It restores the previous CLI subscription
after the run. Tokens are held in memory only, never written into source or state.
